    What are Core Web Vitals?

    Core Web Vitals are the three metrics Google uses to measure real-world page experience: loading, responsiveness and visual stability. Google assesses each at the 75th percentile of page loads, split by mobile and desktop, and a page passes when all three are "good" (web.dev).

    Largest Contentful Paint (LCP)

    The time until the largest image or text block in the viewport is rendered. Aim for 2.5 seconds or less (web.dev/lcp).

    Interaction to Next Paint (INP)

    How quickly the page visibly responds to clicks, taps and key presses, across the whole visit. INP replaced First Input Delay as a Core Web Vital in March 2024. Aim for 200 ms or less (web.dev/inp).

    Cumulative Layout Shift (CLS)

    How much visible content moves around unexpectedly while the page is open. Aim for 0.1 or less (web.dev/cls).

    Field data vs lab data

    Field data comes from real Chrome users through the Chrome UX Report (CrUX), aggregated over the previous 28 days. It is what Google's page experience signals use. Lab data (Lighthouse) is one simulated load in a controlled environment: reproducible and great for debugging, but it can differ from what users actually experience, and it cannot measure INP directly because nobody interacts with the page (web.dev).

    When a URL has too little traffic for CrUX, this checker shows the whole origin's (domain's) field data instead, and says so. Small or new sites may have no field data at all; then use the lab result and Total Blocking Time as a proxy for responsiveness.

    FAQ

    Is this Core Web Vitals checker free?

    Yes. No sign-up, no account, no tracking cookies. It calls Google's public PageSpeed Insights API from your browser.

    Why does it say "not enough real-user data"?

    CrUX only publishes data for pages and origins with enough Chrome traffic. If neither the URL nor its origin qualifies, there is no field data; the Lighthouse lab result is still shown.

    Why is my lab score different from my field data?

    Lighthouse runs one throttled mobile load from a Google data centre. Real users have different devices, networks and cached files, so the numbers often differ. For rankings, field data is what counts.

    How long until fixes show up?

    Lab results change immediately. CrUX field data is a rolling 28-day window, so improvements show gradually over about four weeks.

    What do the canonical and noindex checks mean?

    The canonical check confirms the page declares a valid preferred URL with rel=canonical. The indexing check confirms no noindex meta tag, X-Robots-Tag header or robots.txt rule is blocking the page from search results.

    I see a "rate limit" error. What now?

    Google limits how many free PageSpeed tests can run. Wait a minute and try again, or paste your own free PageSpeed Insights API key when prompted; it is kept only in your browser.
